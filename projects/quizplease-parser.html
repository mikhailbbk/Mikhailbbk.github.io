QuizPlease Parser - Мониторинг расписания

Запущен: 2025 Production Обновлено: Сентябрь 2026

Автоматический мониторинг расписания игр на quizplease.ru через REST API с отправкой уведомлений в Telegram. Работает 24/7 как systemd-сервис, деплой через GitHub Actions.

Python 3.12 Requests REST API Telegram Bot API GitHub Actions Systemd Ubuntu Server JSON CI/CD

Возможности системы

  • Автоматический мониторинг — Парсинг расписания через REST API каждые 30 минут
  • Telegram-уведомления — Уведомления о новых играх и изменении статуса с детализированной информацией
  • CI/CD пайплайн — Автоматический деплой через GitHub Actions при каждом коммите в main
  • Отказоустойчивость — Работает как systemd-сервис 24/7 с автоперезапуском
  • Дедупликация по хешу — Защита от повторных уведомлений, если сайт меняет UUID игры
  • Полная информация — Дата, время, место, цена, статус игры
  • Хранение данных — JSON-файлы с расписанием и историей изменений
  • Минимум зависимостей — только requests, всё остальное — стандартная библиотека Python

CI/CD Pipeline

  • Trigger: Push в main ветку на GitHub
  • Подключение: SSH к production серверу по ключу
  • Обновление: git fetch && git reset --hard origin/main
  • Зависимости: Установка через pip в venv
  • Проверка: Наличие config.py
  • Перезапуск: systemd-сервиса с новым кодом

Ключевые компоненты

  • extract_classic_games.py — Парсер через api.quizplease.ru + логика сравнения
  • telegram_notifier.py — HTTP-клиент к Bot API (без тяжёлых SDK)
  • get_chat_id.py — Утилита получения Chat ID
  • config.py — Конфигурация (в .gitignore)
  • requirements.txt — requests>=2.31.0

Решенные задачи и технические решения

Задача 1: Отказ от HTML-скрейпинга в пользу API

Проблема: Изначально парсинг шёл через BeautifulSoup и HTML сайта. Вёрстка менялась, ломались CSS-селекторы, парсер падал.

Решение: переход на REST API

  • API вместо HTML: Работа с api.quizplease.ru/api/games/schedule/32 — стабильнее и быстрее
  • Меньше зависимостей: Убрали BeautifulSoup, lxml, python-telegram-bot
  • Структурированные данные: JSON-ответ вместо парсинга HTML
  • Устойчивость: API не ломается при редизайне сайта

Задача 2: Обеспечение бесперебойной работы 24/7

Проблема: Система должна работать надёжно и автоматически восстанавливаться после сбоев сети, сервера или API.

Решение:

  • Systemd-сервис: Production-конфигурация с автоперезапуском
  • Комплексное логирование: Логи в файлы и systemd journal
  • Обработка ошибок: Грейсфул деградация при недоступности API
  • Таймауты и retry: Настройка таймаутов и повторов HTTP-запросов

Задача 3: Автоматизация деплоя и обновлений

Проблема: Ручное обновление кода на сервере было трудоёмким и подверженным ошибкам.

Решение: CI/CD пайплайн на GitHub Actions

  • Автоматический триггер: Деплой при пуше в main ветку
  • Безопасное подключение: Отдельный SSH-ключ для деплоя + GitHub Secrets
  • Полный цикл: Обновление кода → зависимости → перезапуск сервиса
  • Идемпотентность: git reset --hard гарантирует чистое состояние

Задача 4: Интеллектуальные уведомления без спама

Проблема: Избегать спама, но своевременно информировать о важных изменениях.

Решение:

  • Только изменения: Уведомления — только при новых играх или смене статуса
  • Полная информация: Сообщения с эмодзи и Markdown
  • Несколько получателей: Поддержка массива chat_ids
  • Идемпотентность: Повторный запуск без изменений ничего не отправляет

Задача 5: Дедупликация игр по хешу

Проблема: QuizPlease иногда меняет UUID игры без изменения содержимого — парсер считал такую игру новой и слал уведомление повторно.

Решение:

  • Хеш от содержимого: Считаем MD5 от дата + время + название
  • Двойная проверка: Сравниваем и по ID, и по хешу
  • Если ID новый, но хеш совпадает — считаем дубликатом, не уведомляем
  • Результат: Нет ложных срабатываний при смене UUID

Задача 6: Безопасность и конфигурация

Проблема: Безопасное хранение чувствительных данных (токены, chat_ids) и простая настройка.

Решение:

  • Шаблон конфигурации: config.example.py для безопасного клонирования
  • Отдельный файл: config.py не отслеживается в Git
  • Встроенная утилита: get_chat_id.py для получения Chat ID
  • Отдельный SSH-ключ: Для CI/CD используется выделенный ключ, не основной

Быстрый старт и использование

Установка

# Клонируйте репозиторий git clone https://github.com/mikhailbbk/quizplease-parser.git cd quizplease-parser # Установите зависимости python -m venv venv source venv/bin/activate # Linux/macOS # venv\Scripts\activate # Windows pip install -r requirements.txt # Настройте конфигурацию cp src/config.example.py src/config.py # Отредактируйте src/config.py, добавив токен бота и chat_ids

Запуск

# Локальный запуск python src/extract_classic_games.py # Как systemd-сервис sudo cp deploy/quizplease.service /etc/systemd/system/ sudo systemctl daemon-reload sudo systemctl enable quizplease sudo systemctl start quizplease # Проверить статус systemctl status quizplease

Управление сервисом

# Статус сервиса systemctl status quizplease # Логи в реальном времени journalctl -u quizplease -f # Перезапуск systemctl restart quizplease # Остановка systemctl stop quizplease # Файловые логи tail -f logs/extract_games.log
